# 06. MVP 범위 및 기술 검증(PoC)

## 1. 출시 우선순위

| 순위 | 범위 | 상태 |
|---|---|---|
| P0 | 단어 카드(표기·읽기·뜻), 한자 훈음·음독·훈독, 발음 듣기, 기억상자 복습, 하루 목표 | v1 포함 |
| P0 | 기출 회차·횟수 표시, 기출만 학습 | v1 포함 |
| P1 | 예문(후리가나·해석·듣기)과 예문 보기 설정, 게임 3종, 레벨·배지, PWA 오프라인, 알람 | v1 포함 |
| P1 | Firebase 동기화·주간 랭킹 | 코드 포함, 설정값을 넣으면 켜짐 |
| P2 | 한자만 따로 외우는 모드(훈음 ↔ 한자), 유의표현 묶음 학습 | 다음 버전 |
| P2 | 사전 녹음 음성(원어민 또는 고품질 합성) | 다음 버전 |
| P3 | 문법·독해 파트, N1·N3 단어장 | 보류 |

## 2. 기술 구성

- React 19 + TypeScript + Vite, 상태는 직접 만든 작은 저장소(`useSyncExternalStore`).
- 데이터는 정적 JSON 한 개(`public/data/vocab.json`, 약 0.4MB). 서버 없음.
- 저장: `localStorage` 기본. `VITE_FIREBASE_*` 환경 변수가 있으면 Firebase 익명 로그인 + Firestore.
- PWA: `vite-plugin-pwa` 로 앱 파일과 단어 데이터를 미리 저장해 오프라인 학습.
- 배포: GitHub → Vercel (빌드 `npm run build`, 출력 `dist`).

## 3. 결정: 로컬 저장 vs 회원제

| 방식 | 장점 | 단점 |
|---|---|---|
| 로컬 저장만 | 서버·비용·가입 없음 | 기기를 바꾸면 기록이 사라짐, 랭킹 없음 |
| 정식 회원제(이메일·소셜) | 계정 보호 | 가입 장벽, 개인정보 관리 부담 |
| **이름 + 공용 가입 암호 (채택)** | 가입이 10초, 지인 그룹만 들어옴, Firebase 를 붙이면 동기화 | 이름을 아는 사람은 그 기록을 볼 수 있음 |

지인끼리 쓰는 학습 앱이고 저장하는 것이 학습 기록뿐이라 세 번째를 골랐다. 가입 암호는 소스에 해시(SHA-256)만 둔다. 불특정 다수에게 공개하려면 정식 로그인으로 바꿔야 한다.

## 4. 기술 위험과 검증 결과

| # | 위험 | 검증 방법 | 결과 |
|---|---|---|---|
| R1 | 기기에 일본어 음성(TTS)이 없어 발음이 안 들림 | 일본어 음성이 없는 브라우저에서 발음 버튼 | 내장 음성이 없으면 온라인 음성으로 재생됨을 확인. 오프라인 + 음성 없음이면 안내 문구 |
| R2 | 내장 음성이 한자를 다르게 읽음 | 단어는 가나 읽기를 넘김 | 규칙으로 해결 (02 문서 7절) |
| R3 | 음성 목록이 늦게 채워져 첫 재생이 실패 | `voiceschanged` 이벤트로 다시 읽음 | 구현 |
| R4 | 기출 원본이 공식 공개되지 않음 | 웹 복원 자료 조사, 출처 간 교차 확인 | 9개 회차 수집. 신뢰도는 회차마다 다름 → `data/kichul_report.md` |
| R5 | 한자가 한국어 글꼴로 그려져 모양이 다름 | `lang="ja"` + 일본어 글꼴 지정 | 구현 |
| R6 | 뜻·예문·훈음의 오류(자동 작성분) | 형식 검사(tools/merge.py) + 표본 검토 | 형식 오류 0. 내용 오류는 `data/fixes.json` 으로 고침 |
| R7 | 카드 뒷면 내용이 길어 넘침 | 375×812 화면에서 한자 4자 + 예문 | 뒷면 안에서 스크롤 |
| R8 | Firestore 문서 1MB 제한 | "학습함" 카드를 id 목록으로 줄여 저장 | 단어 2,000여 개 전부 학습해도 수십 KB |

### 남은 위험

- **온라인 음성**은 구글 번역의 비공식 음성 주소를 쓴다. 약관상 보장된 API가 아니어서 막힐 수 있다. 막히면 내장 음성이 있는 기기만 발음이 나온다 → 장기적으로 P2의 사전 녹음 음성으로 바꾼다.
- **기출 데이터**는 복원본이라 실제 시험과 다를 수 있다. 특히 2023-07, 2024-12 이후 회차의 문맥규정·단어형성 정답은 단일 출처다.
- iOS 사파리는 화면이 꺼지거나 무음 스위치가 켜져 있으면 음성이 나오지 않을 수 있다.

## 5. 브라우저 점검표

| 항목 | 크롬(안드로이드) | 사파리(iOS) | 크롬·엣지(PC) |
|---|---|---|---|
| 카드 밀기·두 번 터치 | 지원 | 지원 | 마우스·키보드 |
| 내장 일본어 음성 | 구글 TTS(기기에 따라 내려받기 필요) | Kyoko 등 기본 내장 | 윈도는 일본어 음성 팩 필요 → 없으면 온라인 음성 |
| PWA 설치·오프라인 | 지원 | 홈 화면에 추가 | 지원 |
| 알림(알람) | 지원 | 홈 화면에 추가한 뒤 지원 | 지원 |

실제 휴대폰에서의 음성 품질은 출시 후 기기별로 확인이 필요하다(개발 중에는 PC 브라우저의 휴대폰 화면 크기로 검증).

## 6. 배포 절차

1. `npm install` → `npm test` → `npm run build`
2. GitHub `Parkdongbae/master-jlpt-n2` 의 `main` 에 푸시
3. Vercel 프로젝트가 저장소와 연결되어 있으면 푸시마다 자동 배포
4. (선택) Firebase: 익명 로그인 사용 설정, Firestore 에 `firestore.rules` 적용, Vercel 환경 변수에 `VITE_FIREBASE_*` 입력

## 7. 완료 판정

- `npm test` 전부 통과, `npm run build` 성공.
- 휴대폰 크기 화면에서: 로그인 → 카드 뒤집기 → 발음 → 기억상자 담기 → 다음 날 복습 → 탈출 → 게임 3종 → 설정 변경이 동작.
- 배포 주소에서 같은 흐름이 동작.
