# 04. 학습 콘텐츠(DB) 스키마

## 1. 데이터 흐름

```
공개 N2 단어 목록(csv) ─┐
KANJIDIC2(xml) ─────────┤ tools/prepare.py ─▶ 번역 작업 묶음(data/work)
                        │                        │ 뜻·품사·예문·훈음 작성 → tools/merge.py
웹 공개 기출 복원 자료 ─┤                        ▼
                        │      data/words.json · kanji_ko.json · kichul.json
                        │      data/extra_words.json · extra_kanji_ko.json · fixes.json
                        └────────────── tools/build.py ─▶ public/data/vocab.json + data/report.md
```

`data/raw`, `data/work` 는 저장소에 올리지 않는다. 사람이 고칠 것은 `data/fixes.json` 에 적고 `python tools/build.py` 를 다시 돌린다.

## 2. 원본·중간 파일

### data/words.json, data/extra_words.json — 단어

```json
{"w": "険しい", "r": "けわしい", "pos": "い형용사",
 "ko": ["험하다", "가파르다"],
 "ex": "この[山道|やまみち]は[険|けわ]しい。", "exko": "이 산길은 험하다."}
```

| 필드 | 설명 | 규칙 |
|---|---|---|
| w | 표기 | 사전형. 접사는 `〜化`, `再〜` |
| r | 읽기 | 히라가나, 가타카나어는 가타카나 |
| pos | 품사 | 명사 / 명사·する / 동사 / い형용사 / な형용사 / 부사 / 접사 / 기타 |
| ko | 한국어 뜻 | 1~3개, 사전식 |
| ex | 예문 | 직접 작성. 한자 어절은 `[한자|읽기]` 후리가나 |
| exko | 예문 해석 | |

`extra_words.json` 은 기출에는 나왔지만 기본 목록에 없던 단어다. 같은 형식.

### data/kichul.json — 기출 항목

```json
{"items": [{"exam": "2023-12", "section": "reading", "word": "険しい", "reading": "けわしい",
            "confirmed": true, "src": [0, 2]}],
 "sources": [{"url": "…", "title": "…", "lang": "zh"}]}
```

| 필드 | 설명 |
|---|---|
| exam | 회차 `YYYY-MM` (07 또는 12) |
| section | reading 한자읽기 / writing 표기 / formation 단어형성 / context 문맥규정 / synonym 유의표현 / usage 용법 |
| confirmed | 서로 다른 출처 2곳 이상에서 일치하면 true |
| src | sources 의 번호 |

문제 문장·보기는 저장하지 않는다.

### data/kanji_ko.json — 한자 한국 훈음

```json
{"険": "험할 험", "楽": "즐길 락 / 노래 악", "込": "담을 (일본 한자)"}
```

음독·훈독·획수는 KANJIDIC2에서 가져온다.

### data/fixes.json — 손으로 고친 것

```json
{"words": {"表記|よみ": {"ko": ["…"]}}, "kanji": {"斉": "가지런할 제"}, "drop": ["表記|よみ"]}
```

## 3. 앱이 읽는 파일: public/data/vocab.json

용량을 줄이려고 배열로 담는다.

```json
{
  "exams": ["2022-07", "2022-12", "…"],
  "words": [["警備", "けいび", 1, ["경비"], "예문", "해석", [[1, "reading"], [5, "writing"]]]],
  "kanji": {"警": ["경계할 경", ["ケイ"], ["いまし.める"], 19]}
}
```

- `words[n]` = [표기, 읽기, 품사 번호, 뜻, 예문, 예문 해석, [[회차 번호, 유형]…]]
- `kanji[字]` = [한국 훈음, 음독, 훈독, 획수]
- 앱은 읽어 들일 때 `id = 표기|읽기`, `freq = 회차 수`, `years`, `secs`, `kanji(표기 속 한자)` 를 계산한다 (`src/store/store.ts`).

## 4. 분류 기준

| 분류 | 값 | 쓰는 곳 |
|---|---|---|
| 품사 | 8종 | 설정 필터, 게임 오답 보기 |
| 기출 여부·연도 | 2022~2026 | 설정 필터, 카드 표시 |
| 기출 횟수 | 0~9 | 새 카드 순서 |
| 문제 유형 | 6종 | 카드 뒷면 표시 |

난이도 등급은 따로 두지 않는다. N2 한 급수 안에서는 "기출 횟수"가 우선순위 역할을 한다.

## 5. 사용자 데이터

기기 저장소 키 `mjn:u:<이름>`, Firebase 연결 시 `n2users/<이름>` 문서.

```ts
UserData {
  name, joined, updatedAt
  settings: { goal, dir, scope, years, pos, order, furigana, showEx, autoSpeak, rate, sound, alarm, alarmTime }
  cards: { [단어 id]: { s: 'l'|'b'|'c'|'d', boxed?, stage?, due?, lr?, n? } }
  days:  { [학습일]: { new, review, boxed, goal, xp, gameXp } }
  xp, best: { quiz, match, read }, badges, tutorial
}
```

- 클라우드에 올릴 때 "학습함" 카드는 id 목록 문자열 하나로 줄인다(문서 1MB 제한 대비).
- 주간 랭킹: `n2ranking/<주 시작일>_<이름>` = { week, name, xp }.
- 두 기기의 기록이 다르면 `updatedAt` 이 더 최근인 쪽을 쓴다.
